# Licensing system — plugin-side reference (LicenSuite license-key flow)

How Animicro Pro consumes the **LicenSuite** licensing backend (Supabase Edge Functions). As of **1.26.0** activation is a **license key**: after purchase the user is emailed a key and pastes it in `/wp-admin`. The plugin validates it against the public `license-check` Edge Function and unlocks Pro. This replaced the v3 OAuth "Connect" flow — see §9 for why and what was removed.

The server-side spec lives in the LicenSuite repo at `~/Desktop/Licence Manager/docs/WORDPRESS_INTEGRATION.md`. This doc covers what happens **inside the plugin**.

> **Why a key instead of Connect?** Emailing a key at the point of sale is far lower friction than sending a buyer to log into an unfamiliar dashboard. The key is the secret; the **multi-site seat limit** (enforced server-side in `license_sites`) is the real anti-sharing control — not any second factor.

---

## 1. Architecture

```
┌──────────────────────┐                          ┌─────────────────────┐
│  WordPress site      │  GET license-check        │ LicenSuite          │
│  yourplugin/         │  ?license=&domain=        │ Supabase Edge       │
│  └─ class-license-   │   &product=               │ Functions           │
│     manager.php      │  Authorization: Bearer    │                     │
│                      │   <ANON_KEY>              │  license-check      │
│  wp_options:         │ ───────────────────────► │  → validates key,   │
│  ├─ ..._license_key  │                           │    registers domain │
│  │    (AES at rest)  │  { valid, plan,           │    in license_sites,│
│  └─ ..._license_data │    expires_at, sites }    │    enforces seats   │
│  └─ ..._premium_     │ ◄─────────────────────── │                     │
│     active           │                           │  license-deactivate │
│                      │  GET license-deactivate   │  → frees the seat   │
│                      │ ───────────────────────► │                     │
└──────────────────────┘                          └─────────────────────┘
```

| Component | Job |
|-----------|-----|
| **`license-check`** Edge Function | Validates `key + domain + product`, activates the domain (respecting the plan seat limit), returns plan/expiry/sites. Called on activation and once per day. |
| **`license-deactivate`** Edge Function | Frees this domain's seat. Called on "Remove key" and on uninstall. |
| **`class-license-manager.php`** | Stores the key (encrypted), validates daily against the live server, premium gating. Self-contained (LicenSuite SDK copy). |
| **The rest of the plugin** | Calls `Animicro_License_Manager::is_premium()` wherever it gates Pro. |

Distribution and licensing are decoupled: the public ZIP is downloadable by anyone, but the key gates Pro at runtime. Stealing the ZIP gets a locked plugin.

## 2. Server endpoints

Both are public Supabase Edge Functions. The **ANON key** goes in the `Authorization` header to satisfy the Supabase gateway's JWT layer (it runs *before* the function code); the key/domain/product travel as **query params**.

### `GET /functions/v1/license-check?license=&domain=&product=`

```
Authorization: Bearer <SUPABASE_ANON_KEY>
```

Success (HTTP 200):
```json
{
  "valid": true,
  "reason": "ok",
  "plan": { "slug": "pro", "name": "Pro", "max_sites": 5 },
  "expires_at": "2027-12-31T23:59:59Z",
  "sites": { "used": 2, "max": 5, "unlimited": false }
}
```

Failures (HTTP 200 with `valid: false`, or 4xx):

| `reason` | Meaning / plugin action |
|----------|-------------------------|
| `not_found` | Key doesn't exist. Don't store it; on a daily re-check, drop a previously-stored key. |
| `invalid_license_format` | Malformed key (caught client + PHP side too). |
| `product_mismatch` | Key is for another product. |
| `expired` / `disabled` | Valid key, can't grant Pro now. Keep the key, lock Pro, keep payload for the UI. |
| `limit_reached` | Seat limit hit. Returns `sites.active_domains`. Keep the key, lock Pro. |
| `rate_limited` (429) | Serve cached state; don't churn the cache. |

### `GET /functions/v1/license-deactivate?license=&domain=&product=`

Same auth/params. Deletes this domain's row from `license_sites`. Returns `{ deactivated: bool, reason, remaining_sites }`.

## 3. Plugin-side files

| File | Role |
|------|------|
| `includes/licensing/class-license-manager.php` | 🟢 Core (LicenSuite SDK copy — generated by `sdk/wordpress/sync.sh` in the Licensuite repo; do not edit here). Key storage (AES), `activate_with_key()`, `deactivate_key()`, daily `validate()`, premium gating, `release_seat_for_uninstall()`. |
| `includes/licensing/class-license-page.php` | License screen (`?page=animicro-license`) — shared SDK admin page: key form / status card / remove, via `admin-post.php`. Same UI in all house plugins. |
| `includes/class-animicro.php` | Loads the SDK + registers the License page; `deactivate()` — a **no-op for licensing** (keeps the key; see §5). |
| `uninstall.php` | Frees the seat (best-effort) + wipes all options on delete. |

### Storage (`wp_options`)

| Option | Contents |
|--------|----------|
| `animicro_license_key` | The license key, **AES-256-CBC encrypted** at rest. |
| `animicro_license_data` | Last good (or last known) payload — plan/sites/expiry/reason, for the UI. |
| `animicro_premium_active` | Hot-path bool, kept in sync by `is_premium()`. |

## 4. Activation & validation

**Activate** (`activate_with_key($key)`): normalize → check format (`/^[A-Z0-9]{4}(-[A-Z0-9]{4}){7}$/`) → `license-check`. On `valid:true`, persist the key + payload and unlock Pro. On any failure, return the reason for the UI and **don't store** the key (the user fixes it and re-pastes).

**Validate** (`validate($force)`): no key = locked → return the cached transient unless forced → `license-check`. Caches the result for `DAY_IN_SECONDS`. Daily forced refresh runs once per 24 h on `admin_init`.

**Fail-soft:** on a transport error or 429, return the last known good payload so a network blip doesn't drop the user out of Pro.

---

## 5. Lifecycle

- **Deactivation** (`register_deactivation_hook`): **does nothing to the license.** Keeping the key + seat means toggling the plugin off/on is instant — no re-activation. (This is the headline change in 1.26.0; the old Connect flow wiped credentials here, which forced a reconnect every time.)
- **Uninstall** (`uninstall.php`, on delete only): calls `license-deactivate` to free the seat, then `delete_option()` for every plugin option. The free build ships without the license manager, so the seat-release is guarded by an `is_readable()` check.
- **Domain change** (`update_option_home`/`siteurl`): flush the validation transients so the next read re-checks (and re-registers the new domain).

---

## 6. Local domains validate for real

There is **no dev bypass**: `localhost`, `*.local`, private IPs, etc. go through the exact same `license-check` call as production domains — the server accepts them and they consume a seat (freed the same way, via "Remove key" / uninstall). What you test locally *is* the real flow.

---

## 7. License screen (shared SDK page)

`?page=animicro-license` is `Animicro_License_Page` (LicenSuite SDK, plain PHP — **not** the React admin). It posts to `admin-post.php` (`animicro_license_activate` / `animicro_license_deactivate`, nonce `animicro_license_action`) and renders: key form (no key), green card (premium), or amber card with the failure reason (stored key blocked: expired / limit_reached / …). The old `animicro/v1/license/*` REST routes and the React `LicensePage` were removed in favor of this page — same screen in all four house plugins.

---

## 8. Premium gating (unchanged contract)

`is_premium()` is the canonical check used throughout the plugin. It **always derives from current state** — key presence → cached validation → premium-slug check — and writes `animicro_premium_active` only as a downstream mirror. `Animicro::is_pro_module($id)` checks the `PRO_MODULES` list (which lives in the `Animicro` core class, not in the SDK).

```php
if ( Animicro_License_Manager::is_premium() ) {
    // load Pro modules
}
```

Hot path per page-load: two `get_option()` reads, no network (the daily refresh is the only network call).

---

## 9. What changed in 1.26.0 (Connect → key)

Removed: the `/plugin-connect` dashboard hand-off, the token `exchange`, the `connect-callback` `admin_init` handler, the `plugin-validate` connection check, `connection_id`/`connection_secret` storage, and the `/license/connect-url` + `/license/disconnect` routes. Replaced by the key flow above. Stale connection options from older installs are cleaned up on next activation and on uninstall. The public API the rest of the plugin relies on (`is_premium()`, `is_pro_module()`, `activate_premium()`/`deactivate_premium()`) is unchanged.

## 10. Hard-learned lessons (still apply)

1. **Probe the endpoint with `curl` before trusting any doc.** A format-valid fake key confirms the whole contract end-to-end (auth header, params, response shape) in 30 seconds:
   ```bash
   curl -s "https://[ref].supabase.co/functions/v1/license-check?license=ABCD-ABCD-ABCD-ABCD-ABCD-ABCD-ABCD-ABCD&domain=example.com&product=animicro" \
     -H "Authorization: Bearer <ANON_KEY>"
   # → 200 {"valid":false,"reason":"not_found",...}
   ```
2. **ANON key in `Authorization`, never a secret.** The Supabase gateway verifies the header as a JWT before the function runs; a non-JWT returns `401 UNAUTHORIZED_INVALID_JWT_FORMAT` and the function never executes.
3. **`plan` is an object `{ slug, name, max_sites }`, not a string.** PHP normalizes any shape; React reads `plan.name` for display, `plan.slug` for gating.
4. **Premium gating is filterable** via `animicro_premium_plan_slugs` (default `pro`/`basic`/`agency`/`enterprise`) so operators can add plans without code changes.
5. **Never early-bail in `is_premium()` on the stored boolean** — a transient bad state would lock the plugin permanently. Derive from current state every time.
6. **`valid: true` is enough — don't also gate on `reason === 'ok'`** (the server may omit `reason` on success).
7. **The ANON key is public — hardcode it** (override via `ANIMICRO_SUPABASE_ANON_KEY` constant / `animicro_supabase_anon_key` filter). Rotation is a normal plugin release.
8. **Local domains are first-class** — the server's reserved-domain rejection was removed on purpose so the whole activation flow can be tested from a local site. Don't reintroduce a client-side dev bypass without also restoring the server rule.
